# E2 — Saved E1 replay on published beta.3

**Disposition: F8 is resolved within E1's bounded saved population on published
beta.3.** On 2026-09-12, published Python `agent-topology-spec==0.1.0b3` and npm
`@agent-topology/spec@0.1.0-beta.3` produced identical full canonical UTF-8 bytes
for all 600 saved E1 population lines and all 16 saved minimized counterexamples.
Every document validated in all four beta.2/beta.3 installations, and every
complete `sha256` / algorithmVersion `1` / value tuple remained equal. This is a
beta.3 disposition addendum to [F8](../../findings/F8-extension-number-canonicalization/README.md),
not a rewrite of E1's beta.2 result or a universal equivalence claim.

This is retrospective **callable** evidence for testbed
[#54](https://github.com/agent-topology/agent-topology-testbed/issues/54), under
[#51](https://github.com/agent-topology/agent-topology-testbed/issues/51). It uses
public installed-package APIs, not a producer or framework execution.

## Question, minimal input and pre-run expectations

Do the two published beta.3 packages close F8 on the exact generated bytes that
exposed it on beta.2? The minimal input is E1's committed
[`inputs.jsonl.gz`](../E1/run-a/inputs.jsonl.gz), its aligned
[`cases.json`](../E1/run-a/cases.json), and the 16 content-addressed JSON files
under [`run-a/minimized/`](../E1/run-a/minimized/). E2 does not import or execute
the Hypothesis generator, create a seed, shrink a new input, or enlarge the
population.

Before installation or replay, [expectations.json](expectations.json) recorded:

- all 600 population lines and all 16 minima validate in the four published
  installations;
- accepted beta.3 Python/npm results have identical full canonical bytes;
- complete structure-hash tuples remain equal across both language and package
  transitions; and
- beta.2→beta.3 full bytes are reported separately per language rather than
  normalized or assumed equal.

These expectations come from accepted upstream [ADR 0009](https://github.com/agent-topology/agent-topology/blob/848b179aee32789a6f8b0ad4552a3a1262a05d55/docs/decisions/0009-numeric-canonical-form.md),
[ADR 0010](https://github.com/agent-topology/agent-topology/blob/848b179aee32789a6f8b0ad4552a3a1262a05d55/docs/decisions/0010-numeric-domain-parsed-value-narrowing.md),
and the [0.1 contract](https://github.com/agent-topology/agent-topology/blob/848b179aee32789a6f8b0ad4552a3a1262a05d55/docs/0.1-contract.md).
[Source references](source-references.json) pin their exact revision and blob IDs.

The pre-install check verified both authoritative E1 captures have identical
compressed population bytes and case manifests. The recorded SHA-256 values are:

| Saved E1 input | SHA-256 |
| --- | --- |
| compressed population | `f6c66aa3e76cb1eee4ec35e510b3ed371f247657e62445e7200049992c91b2ed` |
| uncompressed 600-line stream | `d011b42bd3454be7292e50c7d6d6decdbb840a5b5dece4ee2922c794c5849b48` |
| aligned cases manifest | `6085d9dd7e6f2863e23793692611aaf04d04a9281950a81d6a6b72c40d49f791` |

Each line's digest was also checked against its case row, and each minimum's
bytes were checked against its filename. Both captures retain
[`generator_rerun: false`](run-a/inputs-before-install.json).

## Runs and observed comparisons

[Run A](run-a/comparison.json) and [run B](run-b/comparison.json) each used a
new set of four isolated environments populated only from V2's committed locks.
V2's setup runner reverified registry artifact hashes and import isolation before
E2 streamed the population through the beta.2 and beta.3 batch adapters. Each
minimum and boundary case then ran individually through V2's one-shot adapters.
Python was **3.14.7** and Node was **22.16.0**; the four spec artifact SHA-256
values match V2 exactly.

| Comparison | Equal canonical bytes | Different canonical bytes | Hash tuple differences |
| --- | ---: | ---: | ---: |
| Python beta.2→beta.3, population | 516 | 84 | 0 |
| npm beta.2→beta.3, population | 600 | 0 | 0 |
| Python↔npm beta.2, population | 516 | 84 | 0 |
| Python↔npm beta.3, population | 600 | 0 | 0 |
| Python↔npm beta.3, 16 minima | 16 | 0 | 0 |

Thus the same 84 rows that reproduce F8 on beta.2 change on the Python package
transition; npm beta.2 already used the selected spelling. Beta.3 converges on
the npm spelling for this bounded corpus. Validation, full canonical bytes and
the complete hash tuple are separate fields in every comparison record.

[Repeat verification](repeat-verification.json) compares both captures after
normalizing only installation-specific executable and import paths. Canonical
strings, validation, hash tuples, input digests, non-mutation/idempotence results,
package/runtime versions and verified artifact inventories compare unchanged.

## Unsafe-integer compatibility boundary

Two separately labeled inputs add bare `2^53 + 1` and `-(2^53 + 1)` under an
`x-e2` key. All four packages accept both documents at validation. On beta.2,
Python preserves the parsed arbitrary-precision integer while npm has already
narrowed it, so the pair is **rejected from the cross-language byte-parity
oracle**. That phrase does not mean either package's schema validation rejected
the input. On beta.3, both languages narrow to `±9007199254740992`, produce
identical bytes, and retain the same hash tuple.

This is classified as ADR 0010's package compatibility transition, separately
from F8's saved-population disposition. It is not relabeled as a newly reproduced
F8 defect. Exact per-version results are in each run's
[`boundary_comparisons`](run-a/comparison.json).

## Verification and control

The optimized comparator audited each run during capture. The two-run verifier
then compared all semantic records. Seventeen V1/V2/E2 comparator controls pass;
`test_altered_adapter_result_fails_nonzero` changes one saved beta.3 canonical
string on a temporary copy and requires the comparator to exit **1** with a
`beta.3 canonical mismatch`. No altered evidence is written over either capture.

## Closure disposition

- **Measured claims:** callable comparison of the exact 600-line E1 stream, all
  16 E1 minima and two ADR 0010 boundary inputs across published Python/npm
  beta.2/beta.3, repeated in fresh lock-only environments.
- **Finding disposition:** F8 remains a supported historical beta.2 gap and is
  resolved within this bounded corpus on published beta.3. The unsafe-integer
  rows are a separate compatibility transition, not an F8 defect.
- **Evidence and index:** expectations, exact raw adapter results, comparisons,
  artifacts, command receipts and repeat verification are retained here; the
  [findings index](../../findings/README.md) links this disposition.
- **Decision impact:** consumers can rely on beta.3 cross-language canonical-byte
  parity for these exact inputs and unchanged version-1 structure hashes. This
  does not qualify the release or change any upstream contract.
- **Unresolved evidence:** larger/new populations, other numeric magnitudes,
  runtimes and future versions remain untested. No additional evidence is needed
  for this bounded replay; a broader equivalence claim would require a separately
  scoped population.

## Reproduce

Read [expectations.json](expectations.json), the two boundary files and V2's locks
before installation. Every path must be new:

```bash
rtk proxy python3 probes/published-spec/replay_e2.py --envs .probe-runs/E2/repro-a-envs --out .probe-runs/E2/repro-a
rtk proxy python3 probes/published-spec/replay_e2.py --envs .probe-runs/E2/repro-b-envs --out .probe-runs/E2/repro-b
rtk proxy python3 -O probes/published-spec/verify_e2.py .probe-runs/E2/repro-a .probe-runs/E2/repro-b
rtk proxy python3 -O -m unittest discover -s probes/published-spec -p 'test_compare*.py' -v
```

All commands must exit zero. The altered-adapter comparator invoked inside the
E2 control must itself exit one for that control to pass.

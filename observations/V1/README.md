# V1 — Published beta.1/beta.2 structure hashes

**Disposition: bounded non-finding.** On 2026-09-12, all nine fixed inputs
validated in all four published spec installations. All 36 requested pairwise
comparisons had identical `sha256` / algorithmVersion `1` / value tuples and
identical canonical UTF-8 bytes. Each input ran twice in fresh processes (72
calls), with identical complete adapter records within each installation.
A second, lock-only installation reproduced the result.

This is retrospective **callable** evidence for testbed [#38](https://github.com/agent-topology/agent-topology-testbed/issues/38),
under [#37](https://github.com/agent-topology/agent-topology-testbed/issues/37).
It is neither framework execution nor release-time qualification. Original input
timestamps and historical beta.2 findings, receipts and gallery remain unchanged.

## Question and inspected input

Does the identical accepted document hash identically under the same algorithm
version across published versions and languages? The measurement needs documents,
not producers, framework environments or graph executions.

The eight `conformance/fixtures/*/expected.json` inputs are byte-for-byte copies
from beta.1 source revision `0e127d84d77904dd0a909fab0ea58862282ceae8` (peeled
`v0.1.0-beta.1` annotated tag `a7eedef253514142a4c70f7fdcb1ece78806f1e8`).
[inputs.json](inputs.json) fixes their SHA-256 values and literal expected hash
tuples before installation, at `2026-09-12T12:30:43.325118+00:00`.
No input is regenerated by a producer.

All nine have one graph and format `0.1`. The schema requires at least one graph
but permits empty structural arrays; it requires provenance, completeness and a
hash tuple. The locally authored [minimal input](inputs/minimal.json) keeps just
these requirements. Upstream's file named `minimal.json` was inspected but is
not used: it contains three nodes and optional descriptive fields.
The empty graph's independent oracle is SHA-256 over the UTF-8 literal below;
the resulting value is `16e9f78b7c4e73b5e611f87863fbc8ba9478d7c79582d5031ffce67407cb8421`.

```json
{"graphs":[{"id":"g","structure":{"edges":[],"entryNodeIds":[],"exitNodeIds":[],"joins":[],"nodes":[]}}]}
```

Before extraction, the expected observations were: all inputs accepted; complete
hash tuples match the saved input oracles; repeated results match; four pairings
per input are compared (Python b1↔b2, npm b1↔b2, Python↔npm b1, Python↔npm b2).
Canonical bytes have an independent equality observation, not a hash oracle.

Import/setup failures remain nonzero failures, never non-findings.

## Classification and controls

Only pairs accepted by both packages enter hash comparison. Rejections are
reported separately and make V1's all-valid expectation fail. Equal algorithm
names and versions are required before comparing values. Transitions are retained
with both tuples and return nonzero pending interpretation; they are not called
structural drift. [ADR 0003 at the pinned revision](https://github.com/agent-topology/agent-topology/blob/0e127d84d77904dd0a909fab0ea58862282ceae8/docs/decisions/0003-canonical-ordering-and-versioned-structure-hash.md)
requires a version change when hash coverage/canonical form changes. No transition
occurred here. Canonical differences are recorded independently and do not alone
make a structural comparison fail: descriptive serialization can differ while
the structural hash remains equal.

No semantic normalization is applied to repeated adapter records or canonical
bytes. Run times and process metadata live outside those comparisons; cross-install
comparison explicitly selects validation, canonical bytes and hash tuples.

[Corrupted expected input](controls/corrupted-expected.json) changes only the
recorded oracle for `minimal.json` to 64 zeroes; actual input bytes stay fixed.
The comparator under `python -O` exits **1** and records exactly four oracle
disagreements in [the negative report](controls/corrupted-comparison.json), while
package-to-package comparisons still agree. [Control output](controls/commands.json)
also records seven passing tests: corrupted oracle, algorithm transition,
canonical-only difference, rejection exclusion, missing repeat, API error and
wrong package identity. Synthetic transition/rejection/serialization records are
controls, not observations of package behavior.

graph is the smallest retained input; the eight fixtures bound the tested shapes.
This does not prove stability for every document, Unicode/number/extension edge
case, runtime, platform, dependency resolution, producer output or later release.

Impact trace: the nine document oracles and 36 pairings pass. Separately, the
downloaded Python b2 wheel SHA-256 matches the artifact entry in the pinned
[Python spec qualification receipt](https://github.com/agent-topology/agent-topology/blob/eb0e2d8a95cb2fd0e0daebba18507ab5acdd34fe/docs/releases/evidence/beta.2/python-spec-qualification.json).
That receipt lists artifact-inspection, clean-installation, namespace-coexistence,
package-tests and python-quality. V1 does **not** rerun or requalify that whole
list, nor inspect its sdist. Artifact identity and document structureHash are
different checks; this result supplies no basis for invalidating historical receipts.

Suggested handoff owner: upstream spec/release maintainers, using the linked
contract suites and release installation checks. The incremental candidate is a
maintained same-input, same-algorithm registry-version comparison, reusing this
small corpus/oracle and separate acceptance/serialization outcomes. Graduation
requires the exact regression inputs/oracles to run in an upstream-maintained
verification command or CI, plus a linked owning change and documentation.
**Not graduated:** no such transfer is evidenced or published by this work.
Until adoption, retain this bounded local runner; after confirmed transfer,
retire duplicate maintenance while preserving the observations.

## Reproduce

Read the nine inputs, schema constraints above and locks first. From this repo's
root, use new directory names on every run (the runner refuses existing paths):

```bash
rtk proxy python3 probes/published-spec/run.py --envs .probe-runs/V1/reproduce-envs --out .probe-runs/V1/reproduce-records
rtk proxy python3 -O probes/published-spec/compare.py observations/V1/run --report .probe-runs/V1/comparison.json
rtk proxy python3 -O -m unittest discover -s probes/published-spec -v
rtk proxy python3 -O probes/published-spec/compare.py observations/V1/run --expected observations/V1/controls/corrupted-expected.json --report .probe-runs/V1/negative.json
```

The last command must exit 1; the others must exit 0. The initial capture used
`--resolve --envs .probe-runs/V1/installations --out observations/V1/run` solely
to establish the committed locks. Normal reproduction consumes those locks using
pip `--require-hashes` and `npm ci`; do not rerun `--resolve` to reproduce V1.
